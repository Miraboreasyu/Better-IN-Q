# speedrun_util beta 随从猫静态逆向记录

目标：`0.1.0-beta-8b8f3fddedfe` 附件中的 DLL。此文是静态反汇编证据，不是游戏内验证。不得把规则单测通过等同于 hook / 存档修改实测通过。

## 歌曲

- 入口回调 RVA `0x1e060` / `0x1e090` 先调用原游戏函数，然后以 slot 1/2、猫对象、原返回值调用 `0x1c2d0`；不跳过原游戏函数副作用。
- 签名：slot1 `48 8B C4 53 55 41 57 48 83 EC 50`；slot2 `40 55 56 57 48 83 EC 60 BE FF FF FF FF`。
- 16 项歌曲表 RVA `0xd0b40`，每项 `0x38`：游戏编号、slot、最低参数值、字符串 key 与展示名。游戏编号与表序号不能混用。
- `0xa7a0` 验证猫 `+0x7630 == 1`，`+0xa244` 与本机玩家编号相同，且 `+0x7f7c == 3`（珊瑚）。本机玩家编号来自 `[exe+0x500ec40]+0x248/0x24c`，由 `[exe+0x51c42b8]+0xd2ea == 1` 选择。
- 猫 `+0x8040+gadget*4` 是 0..14 级索引。`exe+0x34a2fd0+index*12` 与 `+4` 给两个选曲参数，不可将 gadget 等级直接当候选数量。
- 猫 `+0xa5e8` 指资源容器，容器 `+0xb8` 数量、`+0xc8` 指针数组。以参数减一取元素，`+0xe` / `+0x14` 给两槽 cooldown。
- 猫 `+0xa4f0` flags，`+0xa508` 30 个 float timers。已奏曲槽1以 bit14..21 与对应 timer 判冷却；槽2以 bit23..29 判断。
- `0x1e0c0` 候选构造：参数 1/2/3/4或5 对应槽1 2/4/6/8 首，槽2 1/3/5/7 首。无资源 metadata 不假造普通候选。
- 特殊状态先强制 `index8`（游戏歌曲0x42）；其余按 status bit0..4、最低参数2/3/3/4/4、timer bit25..29 的顺序强制 index11..15。强制分支优先于普通候选。
- `0x45d90` 选择：forced 优先（ban+skip 才压制）；首曲指定次之，并输出其是否在合法候选里；然后从未ban候选里选最小正rank，平rank优先原结果。没有正rank且原结果未ban就保留原结果。
- 必须替换被ban原结果时，按所有原候选序号加权：槽1权重1/3/5/...，槽2反向。去ban只删对应权重，不给剩余候选重新编号。全ban时skip才返回-1，否则保留原结果。
- 首曲重置以原mod的generation为边界，不能每次编辑设置都把首曲重新触发。

已落地：`src/palico_rules.*` 纯规则；`src/palico_memory.*` 可注入只读内存适配。两个独立 MSVC 测试通过，尚未接入游戏钩子。

## 永久存档字段

- `0x8e30` 当前槽：`root=[exe+0x5013950]`，base=`[root+0xa8]`，index=`uint64(root+0xa0)`；index 必须<=2，槽长 `0x26cc00`。
- `0x9f40` 读猫等级经验：槽 `+0x10265c`；六个 gadget 经验：`+0x102660 + gadget*4`。
- `0xa660` 写经验时锁定槽 `+8` 的锁，同一锁内写目标字段。只写一个猜测等级字节是不正确的。
- `0x8ff0` 经验表：猫资源 `[exe+0x50121d0]`，逐元素 `+0xc` 的 int；gadget 资源 `[exe+0x5012228]` 按 gadget 索引取元素，`+8` 的15个 uint16。容器布局同 `0x9a80`。
- `0x28350` 使用经验表和等级换算辅助函数 `0x46440` / `0x46480`。已核准表项为逐级经验消耗，不是累计阈值：目标等级 L 的经验是前 L-1 项之和；读取等级累计各项并比较，最大等级封顶为表长。累计溢出必须拒绝，不能将表值强制要求单调。
- 出战状态 `0xa5b0`：槽 `+0x1026f8` bit0x10，清位=出战，置位=待命；使用同一槽锁，不能覆盖其它bit。
- `0x21f40` 在Restart流程应用猫装备、猫等级、当前gadget等级与出战配置；不是每次Present或选中UI立即写。

实现永久修改前仍须：核准经验换算/装备原调用、绑定当前真实槽、明确确认、完整备份，失败不可继续写；不自动向游戏目录部署或修改用户存档。

## 辅助猫 / 醉鸟

- CatHelperSetter 签名 `41 57 48 83 EC 50 80 79 30 00 4C 8B F9`，回调 `0x1def0`；只在 `0xa4b0` 检查通过后向对象 `+0x73e0` 写6或8，再调用原函数。
- 6 对应好友解锁检查槽 `+0x102458` bit31；8 对应 `+0x102544` bit30。不能直接绕过解锁门禁。
- DrunkBird 签名 `48 89 5C 24 10 48 89 74 24 18 41 56 48 83 EC 20 48 8D 0D`；回调 `0x1de60` 调原函数后返回1，参数非零时 `0xa540` 向任务 `+0x291d0` 写 byte1。ABI/参数与合法性限制仍需逐项核准。

## 已接入范围（v0.7.3.1 套装页）

- 套装内新增出战 / 随从等级 / 携带道具 / 道具等级四项，默认「不改」；旧配置没有这些键时全部保持原值。
- 只在据点（`pQuest+0x38 == 1` 且 `loading+0x1D04 == 0`，事务内多次复核）随重开应用；局内与未知状态直接跳过。
- 写入前把整槽 `0x26cc00` 备份到 `BetterINQ\backups\palico\*.biqbak`（48 字节头 + 原始槽字节，CREATE_NEW + Flush），备份失败不写。
- 锁用槽 `+8` 的 `CRITICAL_SECTION`（IAT `ce050`/`ce058` 现场核对），非阻塞进入；锁内重验槽身份、`quest/UI/loading` 上下文与除锁外全部槽字节，失败回滚。
- 出战改 `+0x1026f8` bit `0x10`；等级改 `+0x10265c`；道具等级改 `+0x102660 + gadget*4`。
- 携带道具随游戏内随从装备套装 1..24 应用，不写 `+0x2d4` getter。原 DLL `0x9200` 取 `[exe+0x51c4640] -> +0x278 指针数组 -> [0x62]`；`0x22430` 要求对象虚表为 `exe+0x346cfe0`，存档 `slot+0x13b674+(n-1)*0x130` 武器不为空；临时写两项菜单索引后调用唯一 AOB 所指函数 `fn(&obj,0,0)`，再还原并复核索引。
- 发现旧入口探针在 AOB 的 `+7` 位置改写指令，使后续 lazy 原 AOB 扫描必失败。生产不再安装入口探针，并在初始化解析原函数；旧 INI 的 `PalicoProbe=1` 也不再开启该探针。`hook_test.cpp` 增加同字节序列改写后的扫描失败回归。
- 当前修正只证明查找冲突已消除、参数与原 DLL 对齐；不把函数正常返回当作游戏内装备已变。失败输出对象类型/空套装/扫描等原因，成功日志明确标注结果尚未验证。
- 歌曲、CatHelperSetter、DrunkBird 本次不接入。
- 全部为静态逆向 + 隔离单测（`tests/palico_rules_test.cpp`、`palico_memory_test.cpp`、`palico_apply_test.cpp`，25 例），尚未实机验证。
